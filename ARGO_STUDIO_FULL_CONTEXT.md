# PALETTE & TYPE — ARGO Studio Design System

> **File tecnico — owner: Claude (Lead UI Dev)**
> Status: v1.0 — proposta iniziale. Richiede validazione di Andrea su scelta tipografica.
> Tutti i token saranno iniettati in `tailwind.config.ts` e diventeranno la lingua visiva del sistema.

---

## 1. Filosofia visiva

ARGO Studio vive di tre tensioni cromatiche:

- **Vuoto** — neri profondi, atmosferici. La presenza prima della forma.
- **Materia** — silver/chrome. Riflesso fisico, peso, qualità del materiale.
- **Energia** — electric blue glow. Il segnale, il vivo, l'unico colore puro del sistema.

Ogni decisione cromatica deve appartenere a una di queste tre famiglie. Niente è decorativo.

---

| Token | Hex | Uso |
|---|---|---|
| `void` | `#000000` | True black. Base assoluta, hero, transizioni. |
| `obsidian` | `#050507` | Surface primaria. 99% dello schermo. |
| `graphite` | `#0E0E11` | Superfici elevate. Card base, sezioni separate. |
| `carbon` | `#16161A` | Overlay, modal, glass base. |

### Foregrounds — luminanza

| Token | Hex | Uso |
|---|---|---|
| `bone` | `#F5F5F7` | Testo primario. Titoli, body. |
| `pearl` | `#D4D4D8` | Testo secondario. Subheadings, didascalie. |
| `smoke` | `#9CA3AF` | Testo terziario. Caption, metadata. |
| `ash` | `#52525B` | Disabled, placeholder. |

### Chrome — materia

| Token | Hex | Uso |
|---|---|---|
| `chrome` | `#C7C9CC` | Accents premium, dividers luminosi. |
| `mercury` | `#A1A4A8` | Borders subtili, UI ornamenti. |

### Electric Blue — il segnale

| Token | Hex / Value | Uso |
|---|---|---|
| `voltage` | `#4D9FFF` | Primary glow color. Hover, focus, accents. |
| `plasma` | `#0066FF` | Solid CTAs, link attivi, primary action. |

---

## 3. Glass system (glassmorphism controllato)

```css
/* Tre livelli di glass, mai improvvisare */

.glass-subtle {
  background: rgba(255, 255, 255, 0.03);
  border: 1px solid rgba(255, 255, 255, 0.06);
  backdrop-filter: blur(20px) saturate(180%);
}

.glass-default {
  background: rgba(255, 255, 255, 0.05);
  border: 1px solid rgba(255, 255, 255, 0.08);
  backdrop-filter: blur(24px) saturate(180%);
}

.glass-prominent {
  background: rgba(255, 255, 255, 0.08);
  border: 1px solid rgba(255, 255, 255, 0.12);
  backdrop-filter: blur(28px) saturate(200%);
}
```

**Regola:** glass solo quando c'è qualcosa dietro che ne giustifichi l'effetto. Glass su sfondo nero piatto = decorazione vuota.

---

## 4. Glow system

```css
/* Voltage glow — usato come segnale e accento */

.glow-subtle  { box-shadow: 0 0 24px rgba(77, 159, 255, 0.15); }
.glow-medium  { box-shadow: 0 0 48px rgba(77, 159, 255, 0.25); }
.glow-strong  { box-shadow: 0 0 96px rgba(77, 159, 255, 0.40); }
.glow-inner   { box-shadow: inset 0 0 24px rgba(77, 159, 255, 0.10); }

/* Text glow per titoli hero, raro */
.text-glow {
  text-shadow:
    0 0 16px rgba(77, 159, 255, 0.4),
    0 0 48px rgba(77, 159, 255, 0.2);
}
```

**Regola:** glow è raro. Massimo 2–3 glow attivi simultanei per viewport. Glow ovunque = glow nessuno.

# MOTION RULES — ARGO Studio

> **File tecnico — owner: Claude (Lead UI Dev & Motion Engineer)**
> Status: v1.0 — proposta iniziale, in attesa di validazione di Andrea
> Specifiche complete del sistema di animazione del progetto.

---

## 1. Filosofia di motion

Ogni animazione in ARGO Studio deve servire la narrazione cinematica. Non decoriamo, raccontiamo. Il movimento è linguaggio, non rumore. Se un'animazione non aggiunge significato, profondità o ritmo emotivo, va eliminata.

**Regola fondamentale:** se l'utente nota l'animazione invece dell'effetto, l'animazione ha fallito.

---

## 2. Stack di animazione

| Layer | Libreria | Uso |
|---|---|---|
| Smooth scroll | Lenis | Inerzia globale dello scroll |
| Scroll storytelling | GSAP + ScrollTrigger | Sequenze cinematiche, pin sections, timeline |
| Component motion | Framer Motion | Microinterazioni, presence, layout animations |
| 3D / WebGL | Three.js + React Three Fiber | Scene immersive, oggetti interattivi |

**Regola:** nessuna libreria oltre questo stack senza approvazione esplicita.

---

## 3. Easing curves (cinematici)

Custom cubic-bezier curves per tutto il sistema. **NO** `ease` di default, **NO** `linear` (eccetto loop continui).

```ts
// motion/easings.ts
export const easings = {
  // Standard cinematici
  smooth:     [0.25, 0.1, 0.25, 1.0],   // entrata/uscita generica
  smoothOut:  [0.16, 1, 0.3, 1],        // expo-out, decelerazione naturale
  smoothIn:   [0.7, 0, 0.84, 0],        // expo-in, accelerazione drammatica

  // Cinematici premium
  cinematic:  [0.6, 0.05, 0.01, 0.95],  // entrata "movie-grade"
  silk:       [0.4, 0, 0.2, 1],         // tactile, premium hover
  inertial:   [0.05, 0.7, 0.1, 1.0],    // fisica realistica

  // Eccezioni controllate
  spring:     [0.34, 1.56, 0.64, 1],    // overshoot leggero (uso raro)
};
```

---

## 4. Durate

Scala fissa, no valori arbitrari.

```ts
export const durations = {
  micro:    0.15,   // hover state, tap feedback
  fast:     0.3,    // small transitions
  base:     0.6,    // standard reveal, fade
  medium:   0.9,    // section entrance
  slow:     1.4,    // hero reveal, cinematic moments
  epic:     2.4,    // intro sequences only
};
```

**Regola:** mai durata superiore a 2.4s su un singolo elemento. Le sequenze lunghe sono composizione di più step.

---

## 5. Scroll behavior

### Lenis config base

```ts
const lenis = new Lenis({
  duration: 1.2,
  easing: (t) => Math.min(1, 1.001 - Math.pow(2, -10 * t)),
  smoothWheel: true,
  wheelMultiplier: 1,
  touchMultiplier: 2,
});
```

### ScrollTrigger principles

- Ogni section che usa `pin` deve avere fallback responsive su mobile.
- `scrub` solo con valori 1–2 (no `true` puro per evitare jitter).
- Markers OFF in production.

---

## 6. Animation primitives (Framer Motion)

### Reveal pattern standard

```ts
const revealVariants = {
  hidden: {
    opacity: 0,
    y: 24,
    filter: 'blur(8px)',
  },
  visible: {
    opacity: 1,
    y: 0,
    filter: 'blur(0px)',
    transition: { duration: 0.9, ease: [0.6, 0.05, 0.01, 0.95] }
  },
};
```

### Stagger

- Default delay tra figli: `0.08s`
- Hero stagger: `0.12s`
- Lista lunga: `0.04s` max

---

## 7. Performance targets

- **60 FPS costanti** su MacBook 2020 e iPhone 12.
- Solo `transform` e `opacity` per animazioni di rendering. Mai animare `width`, `height`, `top`, `left`.
- `will-change` solo durante l'animazione attiva, mai permanente.
- Three.js: target ~30K poligoni totali per scena hero, lazy load oltre.
- Bundle motion: tree-shaking aggressivo, no GSAP plugins inutilizzati.

---

## 8. Reduced motion

Rispetto assoluto di `prefers-reduced-motion`. Hook globale:

```ts
const prefersReducedMotion = useReducedMotion();
// Disabilita ScrollTrigger pin, riduce durate a `micro`, no parallax.
```

---

## 9. Don'ts

- ❌ Bouncing eccessivo (spring con tension > 200)
- ❌ Animazioni infinite non motivate
- ❌ Parallax aggressivo (max 20% di offset)
- ❌ Hover rotation oltre 6deg
- ❌ Scaling oltre 1.05 su hover
- ❌ Animazioni che bloccano l'interazione utente
- ❌ Easing default (`ease`, `ease-in`, `ease-out` senza custom)

---

## 10. Hover & micro-interactions

| Elemento | Trasformazione | Durata | Easing |
|---|---|---|---|
| Buttons | scale 1.02 max | `micro` | `silk` |
| Links | opacity + slight letter-spacing | `micro` | `silk` |
| Cards | translateY -4px + glow intensify | `fast` | `silk` |
| 3D objects | cursor-driven rotation, damping 0.05 | continuous | inertial |

# AI BEHAVIOR RULES — ARGO Studio

> **File operativo — owner: Claude (parte tecnica) + ChatGPT (parte strategica)**
> Status: v1.0 — sezione tecnica completa, sezione strategica in attesa
> Regole vincolanti per ogni AI che lavora dentro il sistema ARGO.

---

## 1. Principio fondamentale

ARGO Studio non è un progetto generico. Ogni AI che partecipa al sistema lavora come membro di un team con un'identità chiara. La qualità non è negoziabile, l'identità non è diluibile.

**Regola madre:** se un output potrebbe uscire da uno studio template, non è ARGO. Va rifatto.

---

## 2. Ruoli definiti

| Membro | Dominio | Responsabilità primaria |
|---|---|---|
| **Andrea** | Founder & CD | Vision, branding, art direction, decisione finale |
| **ChatGPT** | Strategy & Copy | Posizionamento, narrativa, UX writing, content planning |
| **Gemini** | Research & Inspiration | Benchmark, moodboard, trend analysis |
| **Claude** | Frontend Engineering | Codice, componenti, motion, architettura, build |

**Regola:** nessuna AI deve sconfinare nel dominio di un'altra senza esplicita richiesta. ChatGPT non scrive codice. Claude non riscrive il copy strategico. Gemini non decide architettura.

---

## 3. Regole di esecuzione tecnica (Claude)

### 3.1 Cosa fare sempre

- Pensare in sistemi, non in sezioni isolate.
- Costruire per scalabilità e coerenza.
- Prioritizzare performance (target 60fps, Lighthouse > 90).
- Rispettare il Design System (`PALETTE_AND_TYPE.md`).
- Rispettare le Motion Rules (`MOTION_RULES.md`).
- Modularizzare ogni componente.
- Mobile responsive sempre, non come afterthought.
- Accessibility A11y come requisito, non opzione.

### 3.2 Cosa non fare mai

- ❌ Non improvvisare al di fuori del Design System.
- ❌ Non introdurre librerie fuori dallo stack approvato senza autorizzazione.
- ❌ Non usare colori, font, easing, durate non presenti nei token.
- ❌ Non scrivere codice "preview" o "rough draft" — ogni commit è production-ready.
- ❌ Non aggiungere animazioni decorative gratuite.
- ❌ Non inserire commenti TODO che bloccano la build.
- ❌ Non assumere dettagli mancanti — chiedere se davvero blocca.

---

## 4. Stack tecnico approvato

```
Framework:    Next.js (App Router) + React + TypeScript
Styling:      Tailwind CSS
Motion:       GSAP + ScrollTrigger + Lenis + Framer Motion
3D:           Three.js + React Three Fiber + Drei

```

Qualsiasi libreria oltre questa lista richiede approvazione esplicita di Andrea.

---

## 5. Regole di codice

### 5.1 File structure

```
app/
  (sections)/         # sezioni della homepage come folder co-locati
  components/         # UI components riutilizzabili
  motion/             # easings, durations, variants
  lib/                # utilities, helpers
  styles/             # global, tokens
  layout.tsx
  page.tsx
public/
  models/             # .glb / .gltf
  textures/
  fonts/
```

### 5.2 Naming

- Componenti: `PascalCase.tsx` (es. `HeroSection.tsx`)
- Hooks: `useCamelCase.ts` (es. `useReducedMotion.ts`)
- Utilities: `camelCase.ts`
- Token files: `kebab-case.ts` (es. `motion-tokens.ts`)

### 5.3 Componenti

- Default export per il componente principale del file.
- Props sempre tipizzate con interface esplicita.
- Niente prop drilling oltre 2 livelli (uso context o store).
- Componenti < 200 righe — se cresce, splittare.

### 5.4 CSS / Tailwind

- Solo utility classes Tailwind. Niente CSS module se non strettamente necessario.
- `@apply` solo per primitives ricorrenti (es. `.glass-default`).
